# 0.3.4-alphaの実機アンインストール・再インストール確認

実施日: 2026-11-08。開発用Frameで、起動中のVRChatを終了し、旧専用環境の削除から最新版の再導入・VR起動まで確認した。
配布するWindows EXEから取り出した**同一のpayloadとbootstrap**を、認証済みSSHで実行した試験である。
Windows実機のGUI・初回ペアリング・管理者認証画面を通した試験ではない。

## 使用した配布物

| 対象 | SHA-256 |
|---|---|
| 0.3.4-alpha配布ZIP | `77a29c02800a6e51384ad4bd27d2ec8192bfc3b7066edf6446e7e42e441df9dc` |
| ZIP内のFrameSetup.exe | `304549d5364a8c46fe88802819ef38f110426be195dc0dcebb9cd5b7aaaea9be` |
| EXE内のpayload | `c5e98f85b0bdb845ad951fefd471f4c52fe8277b67304f60a814ed7327f5d95c` |

EXEに含まれるbootstrapと実行した文字列の一致、payloadのハッシュ一致を確認した。
インストール・アンインストールとも終了コードは0だった。

## 削除で確認したこと

- SteamからVRChatの終了を要求し、対象アプリのプロセスがすべて終了してから作業した。
- 通常のアンインストール処理で、旧専用release・使用中Prefixの配置・導入記録が削除された。
- Steamの起動オプションが導入前の値に戻った。
- 旧Prefixは`~/.local/share/frame-pcvr-easy/retained/`へ保管された。写真2枚のサイズ・SHA-256が一致した。
- 作業前の専用releaseと停止済みPrefixも、本人用の復旧データとしてFrame内に保管した。

Steam管理のVRChat本体・FEX・Protonなどは通常アンインストールの対象外であり、今回削除していない。
Steam本体、SteamVR、キーボード、OS、無関係なソフトにも削除操作を行っていない。

## 再導入で確認したこと

- `alpha-dfr-h264-swap-20261108-0.3.4`の専用releaseとPrefixを新規作成した。
- 既存の監査済み専用FEX候補を使わず、固定した上流ソースからFEXを新規ビルドした。
- FEXでのネイティブ終了試験、Vulkanのinstance/device lookup、左右画像2形式の検査が成功した。画像不一致は両形式とも0ピクセル。
- 専用runtimeの16/16ハッシュが一致し、共有FEX・Protonの検査対象ハッシュも変更されていなかった。
- Steamの起動オプションと導入記録が、新しい専用releaseを参照していた。
- 既存の手動8GiB補助スワップを検出して再利用した。スワップのパス・サイズ・優先度は作業前と同じだった。

今回のPrefixは本人の通常Steam環境をもとに新規作成した。保管した旧専用Prefixを自動で戻す試験ではない。
写真などの旧データは保管先に残るが、以前の専用環境のログイン・表示制限・個人設定がすべて引き継がれるとは扱わない。
既存の手動スワップはインストーラー管理外のままで、再起動後の自動有効化は今回検証していない。

## 再起動後の確認

Steamの通常のVR起動を要求した。新しい専用PrefixのVRChatがSteamVRのsceneアプリになり、HMD姿勢が有効、待機グリッドなし、左右コントローラー2台の追跡を確認した。
利用者からも「いいね」と肯定的な応答があった。

- 同じゲームPID・開始時刻のまま描画カウンターが増加した。これはSteamVRの提出カウンターであり、ゲーム内FPSの測定結果ではない。
- 視線共有ファイルのABI・有効フラグを確認し、5秒ごとのsequence更新から発行の継続を確認した。視線座標は記録していない。
- `Job.Worker 0–6`がCPU 3–6、`audio_client_ma`がCPU 0–7に割り当てられていた。起動直後の再試行後に適用成功した記録とも一致した。
- 最後の10秒間の状態確認で読み取った温度は66.4–68.3℃。試験全体の最高温度ではない。

H.264・MF修正の配置はハッシュで確認したが、今回動画を再生してデコード経路や音声再開を再計測したわけではない。
80人インスタンス・COMPLEX7・長時間の安定性も、今回改めて検証していない。

## 確認範囲の限界

今回確認したのは、既存の共有依存部品がある同じFrameでの、0.3.4-alphaの通常アンインストールと再インストールである。
依存部品をSteamから削除・再取得した以前の試験とは区別する。[検証範囲](VALIDATION.md)を参照。
Windows実機での初回ペアリング・GUI操作・sudo認証画面、実Android版からの入れ替え、別Frame・別アカウントは引き続き未検証。

復旧用Prefix、認証情報、写真、実機ログはGit・配布物へ追加していない。
